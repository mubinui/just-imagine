## 1. Verdict

The shared packages match Plan 0 name-for-name, are stricter than the plan in roughly thirty places, and every test passes; this is the strongest part of the repository. The api covers every route in spec 11 and Plan 0 Task 10 with emulator-backed tests, but it still leaks world existence through a 403 and leaves build briefs behind after account deletion. The infrastructure is a Terraform skeleton that validates and encodes most of the Cloud Run table, but nothing can yet deploy: there is no staging pipeline, no promotion gate, no budget, no WIF, and Firestore indexes and App Hosting are not provisioned.

**Single biggest risk:** `cloudbuild.yaml:1-7` only builds an image. The spec's week-1 exit criterion ("staging exists, hello-world deploys of all services") is unmet, so every unverified gate (Vertex model IDs, Live latency, Stripe, the load test, and whether Gemini accepts the raw `responseJsonSchema` the builder sends) is blocked behind infrastructure that does not exist yet.

## 3. API spec coverage

- **Routes.** All fourteen `ROUTES` are mounted at `services/api/src/app.ts:59-133` with the exact methods and paths; `/health` added `:32`. Bodies parsed with the protocol schemas `:87,:94,:126`; path ids through `DocumentIdSchema` `:80-81`; 64 KiB body limit `:26`; CORS restricted to `WEB_URL` `:27-31`; error handler never echoes internals `:33-54` (tested `test/app.test.ts:66-72`).
- **Auth.** Bearer Firebase ID token verified with revocation check (`app.ts:70-79` → `server-core/src/auth.ts:13`). User bootstrap and consent live in `apps/web/app/api/session/route.ts:16-36` (recent-auth 300 s, HttpOnly cookie), not in the api; the api refuses accounts without `consentAt` `store.ts:49-50`.
- **Ownership.** Children are scoped by path, so a foreign child is 404 `store.ts:55-58` (tested `store.integration.test.ts:42-44`). Worlds are not: `getWorld` returns **403** when `ownerUid !== uid` `store.ts:124` and `deleteWorld` inherits it `:180`. Spec intent is 404 (defect 1).
- **Plan limits.** Children limit inside a transaction with a user-doc write to serialize `store.ts:72-94` (race tested `store.integration.test.ts:26-34`). Worlds/day via `reserveWorld` at enqueue (`services/gateway/src/store.ts:186`); saved worlds and images/world in the builder. `usageToday` `store.ts:168-178`.
- **Stripe.** Test-mode keys only `billing.ts:13-14`; Checkout with 7-day trial, price id, success/cancel URLs `:87-98`, reused open session and per-account lease `:17-33,70-81`; Portal `:104-113`; webhook verifies signature `:135`, rejects livemode `:139-140`, handles the three event types `:142-150`, idempotent on `billingEvents/{event.id}` inside the transaction `:156-157,174-181,200`, reconciles from current Stripe state rather than event order `:159-171`, updates `subscriptions/{uid}` and `users/{uid}.plan` `:189-199`. - **Downgrade.** `customer.subscription.deleted` flips `plan` to `free` `:171`; nothing addresses a family account holding 2 to 4 children or more than 10 saved worlds afterwards (existing data stays, new creation blocked). Undefined rather than wrong; needs a product decision.
- **Deletion jobs.** Durable `deletionJobs` with fences (`deletionLocks/{uid}`, `users/{uid}/deletionLocks/{childId}`, `worldDeletionLocks/{worldId}`) `deletion.ts:14-39`; leased, idempotent worker `:40-112`; Cloud Tasks dispatch with OIDC `tasks.ts:10-25`; 5-minute Scheduler retry `infra/terraform/main.tf:292-311`; cloud start refuses to run without a queue `main.ts:42-43`; Auth cleanup tolerates `user-not-found` `deletion.ts:88-98`. Gaps: `builderJobs` are never deleted (defect 2); fences and job shapes are hard-coded strings in six files with no protocol schema (defect 5).

Rules test `test/rules.integration.test.ts` proves own read 200, foreign read 403, client PATCH 403, unauthenticated 403 through the emulator REST API with a real token. ## 5. Defects (severity order, security first)

1. **Ownership oracle on worlds (medium, security).** `services/api/src/store.ts:124` throws `forbidden()` (403) when `world.ownerUid !== uid`; `deleteWorld` `:180` inherits it. A parent who learns or guesses a `worldId` can confirm it exists and belongs to someone else. Spec intent and Plan 0 brief: 404. Fix: `throw missing()` and assert 404 in `store.integration.test.ts:52-56`.
2. **Account and child deletion leave `builderJobs` (medium, privacy).** `services/api/src/deletion.ts:72-100` deletes worlds, sessions, children, usage, subscription, billing state and the Auth user, but never queries `builderJobs` (indexed by uid at `firestore.indexes.json:34-46`), which hold the child's build brief (`description`, `conversationSummary`) and ids. Spec 10 promises sessions, discoveries and worlds are gone within 24 h; the brief outlives them. Scenario: parent deletes profile; `builderJobs` for that child remain indefinitely.
3. **Builder sends a schema Gemini may reject (medium, correctness, cross-area).** `services/builder/src/vertex.ts:56` passes `generatedSceneJsonSchema()` raw as `responseJsonSchema`: 83 `additionalProperties`, a `$schema`, and `propertyNames` for `variables` (from `z.record(IdSchema, …)` at `scene-schema/src/schema.ts:175`). `toGeminiJsonSchema` (`json-schema.ts:5`) is unused and in any case leaves `propertyNames`, `const` and `pattern`; its test `test/json-schema.test.ts:34-41` only asserts three keywords. Scenario: first real `generateContent` call fails with an invalid-schema error and every build falls back to a fixture. Unverifiable offline; must be the first staging smoke.
4. **api Cloud Run timeout drifts from the spec (low).** `infra/terraform/main.tf:8` sets 300 s; spec 13 says 60 s. Probably deliberate for the internal deletion worker (`tasks.ts:22` dispatch deadline 300 s), but undocumented. Decide and record it in the runbook or split the worker.
5. **Fence and job documents are untyped, duplicated string paths (low, maintainability).** `deletionLocks/${uid}` is spelled in `server-core/src/quota.ts:50`, `api/src/store.ts:47`, `api/src/billing.ts:35`, `gateway/src/store.ts:47`, `builder/src/worker.ts:64`, `apps/web/app/api/session/route.ts:18`; `deletionJobs`, `billingLocks`, `billingState`, `billingEvents`, `worldDeletionLocks`, `builderJobs` have no `paths` entry and no Zod schema in protocol, against the master-plan rule that every cross-service document has one. Scenario: one spelling change breaks a fence silently (no test spans all six).
6. **Builder ingress is public (low, defence in depth).** `main.tf:185` uses `INGRESS_TRAFFIC_ALL` for all three services; builder is only invoked by Cloud Tasks (internal traffic) and could use `INGRESS_TRAFFIC_INTERNAL_ONLY`.
7. **Webhook calls Stripe before the idempotency check (low).** `billing.ts:152` retrieves the subscription, then `:157` checks `billingEvents`. Stripe redeliveries cost two reads and a transient Stripe error on an already-applied event returns 500, so Stripe keeps retrying. Move the `billingEvents` read before the Stripe call.
8. **Kill switch re-activation after a doc delete is not logged (low).** `server-core/src/kill-switch.ts:28-31` calls `onChange(false)` without `observed()`, so `lastObserved` stays `true`; a later re-enable does not emit `kill_switch_on`, which the alert `observability.tf:123` keys on.
9. **Deletion is not re-authenticated (low).** `app.ts:118-124` accepts any live ID token for `/v1/me/delete`; the 300 s recent-auth check exists only at sign-in (`session/route.ts:14`).
10. **`me()` ignores child fences (low).** `store.ts:62-66` lists all children, so a child mid-deletion still appears in `/v1/me` while `child()` `:55` already hides it.
11. **CI timeout (low, operational).** `ci.yml:14` allows 20 minutes for install, emulators, Next build, Chromium install and Playwright; expect flaky timeouts.
12. **Unbounded list queries (low).** `store.ts:129-133,152-156` return every world/session and sort in memory; the composite index at `firestore.indexes.json:3-17` is declared but unused.
