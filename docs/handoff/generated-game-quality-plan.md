# Generated game quality

2026-10-17. Codex owns this bounded pass under the user's standing instruction to plan deeply and execute. Preserve Claude's Schools/STEM claims and all existing language, story and motion work.

## Research

The family pipeline already generates scene-specific JavaScript, with no fixed genre catalogue. `imagine-game.ts` checks syntax, sandbox limits, ten simulated seconds and child-facing moderation. However, `drive.ts` only taps dynamic sprites, never taps empty destinations, flicks the hero artificially, and answers every question with option zero. It cannot prove that requested interactions work. The independent scene review checks physical layout before art, not behavior.

`GameScriptModel` shares `SCENE_MODEL`; local compose selects Flash. Argon is documented as the builder default but is not the local game author. Game authoring must have its own explicit model and region. Do not silently downgrade. Keep image and Live models separate.

Dependencies: builder main → worker → initial/edit behavior compilation → game-runtime Node host → real engine. No saved-world schema migration, new browser engine or shared school contracts are needed.

## Execution

1. Give game authoring `GAME_MODEL` and `GAME_MODEL_LOCATION`, bounded requests and explicit reasoning configuration. Verify Argon access with the existing key before claiming it works.
2. Generate a small structured acceptance plan from the actual child words and scene **before the script exists**. Include the child's controls, visible consequences, exclusions and representative journeys. The programmer receives this plan; tests cannot be invented afterward to excuse the implementation.
3. Extend the existing driver with explicit timed tap, drag/release, flick and answer playback and trusted state observation. Explicit playback disables generic tapping/flicking/automatic answers. Preserve existing smoke tests.
4. Run data-only bounded scenarios against fresh real physics worlds. Check destinations, rest speed, displacement, existence and specific command consequences; reject missing targets, invalid times, empty checks and trivial checks. Keep open play free of compulsory scores/timers/endings. Feed precise failures into the existing two-attempt repair loop; failed edits preserve the previous world.
5. Add red/green tests for no-op and cosmetically disguised scripts, static characters, empty-space taps, correct movement/rest, reversed state, option selection and malformed plans. Run targeted packages, then real Argon generation/playtests. Inspect a real creative example in the browser if browser tooling is available.
6. Rebuild local app services after verification, preserve persistent demo data and document evidence and remaining limits.

## Acceptance and limits

A successful code run is insufficient: the requested causal interaction must pass a prewritten physical or state assertion. No-op scripts and a runner stuck behind scenery must fail. Plans and tests are internal, never restrictions on the child's imagination. Model planning is still fallible; this is a measurable publication gate, not a guarantee of enjoyment or film-quality animation. This pass strengthens arbitrary generated gameplay and preserves the native motion-art pipeline; new articulated rigs, 3D engines, arbitrary network/code access and the school product are separate work.

Complexity: high. Risks: model availability, extra planning latency, incorrectly strict acceptance plans, physics tolerances and accidental synthetic-input interference. Bound plan size/duration and model retries, use fresh deterministic worlds, keep failure honest, and record real-service results separately from doubles.

## Visual acceptance finding and bounded correction

The fresh full browser creation passed its controls but screenshots showed a forest covering a correctly generated starfield. Downloading both real plates isolated the cause: the optional mid-layer was another opaque landscape, rendered above the backdrop. This is a concrete creative-fidelity defect, not a subjective art change. Extend this pass to `packages/engine/src/{textures,renderer}.ts` and builder layer-art processing: reject opaque secondary layers at rendering (including existing saves), generate sparse keyed overlays on the full16:9 canvas with a separate cache version, and validate transparency before storing. Preserve sprites, existing transparent overlays, original saves and all physical bodies. Add real-pixel alpha and lifecycle tests, then recapture the same generated artwork and controls after the fix. No new engine, schema migration or school surface is involved.
