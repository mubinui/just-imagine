# Engine review

Verdict: **changes required**. Static review of the brief, spec sections 5.6 and 6, supplied diff, implementation, schema/material table, and seven existing tests. No tests rerun and no implementation edits. The reported passing tests establish a useful headless baseline but do not cover the failures below. No critical security finding identified; the following are important correctness/acceptance findings.

1. **Body patches silently delete document joints; joint patches reset unrelated simulation state.** `simulation.ts:285-305` removes and re-adds changed bodies. Rapier removes attached joints when a body is removed, but this path never recreates `doc.joints`. Resize a pendulum bob without changing the joint JSON: the bob becomes detached. Conversely any joint JSON change calls `load`, resetting every pose, clock, rule-once state, challenges and history. Reconcile affected joints in place and retain unaffected runtime state (spec 6.3).

2. **Progressive updates ignore new/changed variables and may resurrect removed bodies.** `simulation.ts:304-311` adds every document entity absent from runtime, including an entity previously removed by a rule. A subsequent asset-only update brings it back, violating preservation of runtime state. `update` also replaces the document without reconciling variable values/bindings: adding a lab slider does not initialize its value or apply its binding, and removing one retains its snapshot value. Track runtime removals separately from new document entities, and reconcile variables explicitly.

3. **Density sliders do not affect buoyancy correctly; float-everything does not float dense bodies.** The material variable at `simulation.ts:545-551` changes collider density only; buoyancy at `609-621` still divides by the original document material density. Changing wood density above water therefore still makes it float like wood, undermining the density lab. `floatAll` uses that same inverse-density force, so stone/metal still accelerate downward. Use effective runtime density for normal buoyancy and a distinct spell buoyancy override. Existing spell test only checks timeScale after restore.

4. **Restore changes polygon collision geometry, even for an unrelated spell.** `simulation.ts:459-470` replaces every non-circle collider with a cuboid. `castSpell('restore')` calls `scale` for all entities (`564-565`), including unchanged static polygon ground. Thus slowTime followed by restore permanently replaces polygon geometry with rectangles. Preserve/scalably reconstruct each original collider shape; do not mutate unaffected shapes on restore.

5. **Flick release discards the gesture velocity.** `renderer.ts:315-326` retains only the last pointermove and estimates velocity from pointerup minus that point. Browsers commonly deliver pointerup at the last move position, yielding zero velocity and stopping a fast flick. Spec 6.4 requires the last 80 ms of movement. Keep a bounded timestamped movement window, and handle pointercancel as cancellation rather than launch. Drag also sets velocity only when pointermove arrives, so a stationary held pointer does not continue constraining a falling body; there is no persistent hold or tap highlight.

6. **Histogram challenge completes on presence, not accumulated trials.** `simulation.ts:696-712` recreates bins from current positions every sample and completes histogramFilled when the number of currently tagged bodies reaches count. A Galton-board challenge can complete while balls are still at the top, and trials disappear on removal. The report acknowledges this limitation, but it leaves the explicit probability-lab use case incomplete. Record bounded landing samples or define and implement the intended accumulation semantics before acceptance.

7. **Soft-body implementation retains a full rigid collider inside the lattice.** `simulation.ts:197-229` creates the normal full-size collider, then uses that rigid body as the lattice center, adding eight circles. This is not the specified grid of nine small circles; collisions are dominated by an undeformable full-size box/ball. Nonzero initial rotation is also applied only to the center; outer nodes start axis-aligned. Correct the center collider and rotate initial offsets. The existing test checks nine nodes and finite center y, which cannot establish jelly deformation quality. Runtime material switching also never creates/removes the lattice, as the report acknowledges.

8. **Bounded live entity count does not bound retained runtime/cache memory.** Removal (`simulation.ts:423-435`) leaves `scales`, `launches`, and `submerged` entries; repeat spawn/grow/remove cycles leave unique spawn IDs indefinitely. Removed/replaced visual IDs also retain plot/histogram maps on update. Renderer uses globally cached `Assets.load` textures without unloading/releasing replaced URLs. Long-lived progressive editing can accumulate assets even after containers are destroyed. Clean per-entity/visual state on removal and establish texture ownership/release on update/dispose.

9. **Renderer hot path deep-clones all history multiple times per frame.** `renderer.ts:131-137` calls full `snapshot()` before each tick and again for rendering; `snapshot` clones up to 600 frames, all plots and 2,000 inputs. At 24 soft bodies this repeatedly copies tens of thousands of node/pose objects per frame in addition to rebuilding every Text/Graphics overlay. This is a concrete performance risk against 60 fps on iPad; expose a lightweight current-frame snapshot and retain overlay objects. No browser/device evidence currently validates this budget.

10. **Async asset sequencing delays placeholders and first paint.** `renderer.ts:61-125` awaits backdrop and mid-layer loads before creating entity placeholders, then awaits each sprite serially before creating later placeholders. Slow network asset requests can leave an empty canvas or an incomplete world long after the document arrives, contrary to progressive presentation and the 500 ms fixture first-paint target. Build all placeholders immediately and resolve assets independently with the existing generation guards.

Coordinate/lifecycle notes: the implementation consistently uses screen-down positive y with positive gravity, negative launch-y and height = 9-y; that agrees with the supplied examples and fixed 16x9 bounds. Revolute joint anchors, however, subtract world positions without inverse-rotating into each body's local frame (`simulation.ts:172-175`), so initially rotated bodies receive incorrect pivots. Normal renderer disposal removes ticker, pointer handlers and observer and guards late texture attachment; headless dispose is idempotent. Failed Pixi init disposes the simulation but does not destroy the partially initialized Application. Browser teardown, fallback, pointer behavior and performance remain unverified.

Acceptance: keep the headless deterministic/immutable baseline and asset-only pose preservation evidence, but do not mark full physics, progressive patches, interactions, lab visuals, bounded memory, or browser performance complete until the issues above are addressed or explicitly accepted as scope reductions. Add focused regressions for joint/body patches, rule-removed entities during asset updates, effective density buoyancy, polygon restore, gesture velocity and histogram completion; obtain browser lifecycle/interaction evidence.

## Fix round 1 scoped re-review

Verdict: **changes still required**, with substantially improved coverage. Static source/test review only; accepted the controller's 25 passing tests, typecheck/lint and real WebGL lifecycle evidence without rerunning them. Scope is the original findings and the newly added collider loading.

Original findings 1, 3, 4, 5, 6, 7, 9 and 10 are addressed in their principal reported failure cases: joints reconcile without load, effective density/float overrides are separate, polygon scale reconstruction preserves shape, gesture samples and persistent spring anchors exist, settled trials accumulate, the full rigid lattice center is gone, rendering avoids history snapshots and retains overlays, and placeholders are synchronous. Inverse-rotated initial pin anchors and failed-init cleanup are implemented. Finding 2's tombstones and variable-definition reconciliation and finding 8's per-entity/cache cleanup are also implemented. Device frame-rate acceptance remains unproven; the reported browser smoke is useful lifecycle evidence and is correctly distinguished from iPad profiling.

Remaining concrete issues within this scope:

- **Important — active material bindings are lost on a body patch while the slider still reports the old value.** `simulation.ts:428-435` deletes effective material before rebuilding, and `455-458` only reapplies variables whose definitions changed. Set a density slider to a non-default value, resize that same body's document geometry, and update: its density/buoyancy return to document defaults while `frame().variables` still shows the selected density. This leaves the original variable/update correctness issue partially open. Reapply unchanged active bindings to rebuilt bodies using current runtime variable values, with explicit precedence for changed material documents.

- **Important — collider replacement does not invalidate the prior collider source.** `simulation.ts:261-280` preserves colliderParts on every rebuild and `update` only copies the new asset at `443`. If a ready auto-shaped entity changes to a different asset/collider URL, the previous outline remains active until fetch success; if the new collider is absent/invalid/fails, the previous outline remains permanently. This contradicts the reported fallback to placeholder physics and can make the new painted sprite collide as its old silhouette. Associate accepted parts with their asset/collider identity, clear them on source changes, and use the placeholder until a valid replacement arrives. A same-source asset update should retain the accepted outline and pose.

- **Important — collider fetch is not actually bounded to 64KB.** `renderer.ts` loadCollider calls `await response.text()` before checking raw length. A large or unending collider response allocates/buffers the entire body before rejection; the stated cap therefore does not protect the browser's bounded-memory requirement. Stream response bytes with a hard byte limit and abort as soon as exceeded; use Content-Length only as an early check. Existing setCollider parser tests do not exercise fetch-size enforcement.

- **Important — replacement auto colliders drop water sensor semantics.** In `simulation.ts` add(), the initial collider sets `.setSensor(e.kind === 'water')`, but the replacement convex-part descriptors do not. A water entity with body.shape='auto' and a valid colliderUrl changes from a pass-through fluid region into solid obstacles once its asset resolves. Preserve sensor behavior on every replacement collider. Test a dynamic body crossing an auto-shaped water entity before/after collider arrival.

Additional bounded-memory caveat from the new texture path: failed TextureLease requests remain cached as rejected promises while the URL stays referenced. A transient failure cannot recover on a later same-URL progressive update. Evict failed entries (disposing any partially created bitmap) so the next acquire can retry. This is a recoverability issue, not evidence that the successful ownership/late-decode cleanup failed.

Required follow-up is focused regressions for these remaining cases and corresponding fixes; there is no need to reopen unrelated engine features for this review round.

## Fix round 2 scoped re-review — ledger closed

Verdict: **all remaining scoped review findings addressed**. Read the round-2 report, modified implementation and focused regression tests. No tests rerun and no implementation edits; the controller reports 33 tests, typecheck and lint passing, including real Rapier Galton Board/Fractions playthroughs.

- Active bindings: update tracks rebuilt bodies and reapplies unchanged entity bindings using current runtime values. Changed variable definitions initialize their new values. The density/scale regression covers a simultaneous geometry and material-default patch and checks resulting motion, closing the remaining variable/update finding.
- Collider source identity: changes to sprite URL, collider URL or status invalidate accepted parts; rigid bodies with an old outline rebuild fallback geometry while retaining pose. Same-source updates retain outlines, and soft bodies discard stale stored outlines without reconstructing their node poses. The new source-replacement regression covers fallback and preservation.
- Bounded response reading: readBoundedJson uses a fixed 64,000-byte buffer, checks each chunk before copying, and aborts/cancels on overflow. Content-Length can reject before reading. Tests exercise streaming overflow, cancellation, no response.text call and a valid bounded response. This closes the unbounded buffering finding.
- Water sensor behavior: every generated convex part now preserves setSensor for water; a real Rapier before/after comparison verifies pass-through motion.
- Texture retry: rejected requests evict only their own cache entry and release partial resources. The same-URL retry regression verifies a transient fetch failure can recover.

No additional important breakage identified in these scoped fixes. The original findings and round-1 follow-ups are closed for this review. Actual iPad frame-rate profiling and visual/interaction acceptance remain the explicitly recorded device-QA limitation; this verdict adds no device-performance claim.
