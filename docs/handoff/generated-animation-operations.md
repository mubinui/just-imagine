## Source and behavior

- `services/builder/src/assets.ts` keys the whole sheet, registers complete alpha silhouettes and packs them with one scale and a ground/body-center anchor. Production auto mode permits 6, 9 or 12 complete poses in three aligned columns and clear rows. Explicit-count callers remain strict. Extra/merged/clipped subjects, ambiguous fragments, uneven rows and unresolved backgrounds fail; nominal grid dividers never cut tails or wings.
- A known magenta/green key is recognized only when it dominates over 95% of the outside edge. A narrow measured RGB key match clears enclosed gaps; a connected exterior matte handles tint. Hue despill is limited to two pixels from a frozen clear mask, preserving indigo/green clothing. Exact foreground/key-color collisions remain ambiguous and may need the alternate-key retry. Ordinary static sprites retain previous processing.
- `vertex.ts`, `motion.ts` and `worker.ts` give animated actors the hero image model, square 2K requests, 60s HTTP/65s abort and one SDK attempt. At most two asset attempts run. Registration failures supply fixed repair instructions and a normalized PNG identity reference. Safety/matching-rejected art never becomes a reference. Mandatory review approves the actual frame count and requested identity before cache/file publication. Review itself uses 15s HTTP/20s abort and one SDK attempt.
- Native detail supports 512 px cells only when source dimensions and pose extent permit it; otherwise cells remain 256 px. Nine frames may yield 1536×1536, twelve 1536×2048. New articulated cache version is `motion-v5`; rolling chassis remains `motion-v2`, ordinary cutouts stay unchanged, and saved worlds are not regenerated. Existing ready bitmaps without required animation can be retried on edits; failed replacements preserve the last valid world.
- Fixed telemetry distinguishes request, registration/count/layout/background, review and storage failures using operational IDs/counts, without child text, provider messages or credentials. Missing required motion fails honestly instead of publishing a ready static placeholder.
- Protocol jobs carry optional bounded `childRequest`. `gateway.ts` captures typed or moderated final spoken words separately from a model summary, retains at most four whole safe turns, serializes moderation, blocks queued creation after rejection and clears history at build/edit/new-game/end boundaries. `live.ts` flushes available child ASR before tools. Scene/script/edit prompts preserve actual choices and exclusions under safety/language policy. Canonical wish/edit metadata retains actual words; old jobs fall back to previous fields.
- `prompts/world-design.ts` (`wd4`, mirrored in `docs/art/world-design-principles.md`) normally stages a main actor 3–4 m across a 16 m world, while honoring explicit child sizes and balanced casts. Story/challenge structure is optional. Guidance forbids unrequested blocking scenery, particle bodies, scores or timers; physics/art dimensions remain aligned. `wd4` removes contradictory compulsory-obstacle guidance.
- `creation-review.ts` / `VertexModels.reviewScene` independently check concrete exclusions and physically blocked requested routes before behavior/art. The existing maximum three scene attempts carry review feedback and the previous candidate. Strict consistent JSON, 15s HTTP/20s abort and one SDK attempt fail closed. Edits include the previous owned scene; explicit validated Labs retain their path. Requested obstacles/collision challenges remain valid. There is no silent collider deletion or unlimited repair loop. Fixed review telemetry records only job ID, approval and issue count. This semantic gate is not a mathematical proof of every game.
- `presentation.ts` marks only the full-width static base floor as painted when an approved backdrop exists. Collision stays intact; platforms, walls, Labs and missing-art placeholders remain visible. `packages/engine/src/renderer.ts` includes body/kind/tags in display identity, replacing a streamed loading rectangle when its painted presentation tag arrives. No new engine sensor or movement API was added.
